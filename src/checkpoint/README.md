# Checkpoint Module (`src/checkpoint/`)

## Overview

The `checkpoint` module manages serialization, preservation, and restoration of training checkpoints. It saves model weights, optimizer states, scheduler conditions, and training history metadata to enable fault-tolerant resumes.

## Key Features

- **Decoupled Architecture**: Cleans compiled modules (e.g. models optimized with `torch.compile`) by stripping framework wrappers (`_orig_mod.`) before writing state dicts to disk, ensuring compatibility with standard inference engines.
- **Save Strategies**: Supports saving the "best" model based on target validation metric (e.g., QWK) and saving the "latest" state for quick training resume actions.

## API & Interfaces

### Classes

#### `CheckpointManager`
The primary operator for state serialization.
- **`__init__(directory: Path, monitor_metric: str = "qwk", mode: str = "max")`**
- **`save_epoch(model, optimizer, scheduler, state: TrainerState, filename: str) -> None`**
  Writes active state dictionary including models, optimizers, learning rate schedulers, and current training progress metadata.
- **`save_best(model, optimizer, scheduler, state: TrainerState) -> None`**
  Updates the "best_model.pt" weights if the monitored metric improves.
- **`load(filepath: Path, model, optimizer=None, scheduler=None) -> TrainerState`**
  Restores state dict from disk into active runtime instances.

### Functions

- **`clean_state_dict(state_dict: dict) -> dict`**
  Cleans weight keys by removing `_orig_mod.` or `module.` prefixes generated by compiled or distributed PyTorch engines.

### Exceptions

- `CheckpointNotFoundError`: Raised if target weight files do not exist at the designated path.
- `InvalidCheckpointError`: Raised if checkpoint loading fails validation (e.g., keys mismatches, corrupted data).

## Dependencies

- `torch`: Main state dictionary serialization (`torch.save`, `torch.load`).
